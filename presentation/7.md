# Development Checklist — Local Setup & Admin UI Tasks

This slide enumerates atomic tasks to get the project running locally, create DB entities, secure access, and implement the admin UIs and agents. The admin provides the studied (source) and native (target) language via dropdowns in the UI.

---

## Environment & Core Services

1. Create Python virtual environment for the project (venv/pyenv/pipx).
   - Estimate: 0.5h
2. Install backend Python dependencies:
   - `fastapi`, `uvicorn`, `sqlmodel`, `alembic`, `pydantic`, `httpx`, `jinja2`, `htmx` (templates), `requests`.
   - Estimate: 1.0h
3. Install AI stack libs:
   - `langchain`, `langgraph` (or your LangGraph package), `openai` / SDK, `langsmith` client (if available).
   - Estimate: 1.0h
4. Configure OpenAI API key and other AI credentials via environment variables (`OPENAI_API_KEY`, `LANGSMITH_KEY`, etc.).
   - Estimate: 0.5h
5. Install and run Supabase locally via Docker Compose (Supabase Docker stack).
   - Estimate: 1.5h
6. Ensure Postgres has the `pgvector` extension enabled (create extension if needed).
   - Estimate: 0.5h
7. Add local-run scripts (`scripts/start-local.sh` or `Makefile`): start Supabase Docker, start backend, run migrations.
   - Estimate: 1.0h

Section subtotal: 7.0h

---

## Database & Migrations

8. Create DB user(s) and an initial `admin` role. For local dev, grant broad privileges to `admin` only.
   - Estimate: 0.5h
9. Add `pgvector` to DB (extension); confirm via `SELECT extname FROM pg_extension;`.
   - Estimate: 0.25h
10. Create Alembic migrations (models → alembic revision) for all entities: languages, word_categories, grammar_rules, grammar_rule_rows, base_words, word_forms, topics, sentences, entity_embeddings, etc.
    - Estimate: 3.0h
11. Run migrations against local Supabase/Postgres.
    - Estimate: 0.5h
12. Seed minimal data:
    - Create an initial `admin` account (or import) and at least one `language` entry if desired.
    - Estimate: 1.0h

Section subtotal: 5.25h

---

## Auth & Policies

13. Configure Supabase Auth: enable email/password provider, set site URL, and configure JWT settings.
    - Estimate: 1.0h
14. Define RLS policies so only `admin` role can perform writes; allow read access to needed resources for debugging/testing.
    - Estimate: 2.0h
15. Add privacy policy and terms links in the admin UI; store policy documents in project `docs/` and wire to Supabase settings.
    - Estimate: 1.0h
16. Implement backend JWT issuance & verification (FastAPI dependency). The UI login page should POST credentials to backend and receive a JWT.
    - Estimate: 2.0h

Section subtotal: 6.0h

## Admin UI — Authentication & Onboarding

17. Implement login page (Jinja2 + HTMX) that uses backend auth endpoint and stores JWT (HttpOnly cookie).
    - Estimate: 2.0h
18. Implement an initial `Languages` admin page:
    - Dropdowns for `source_language` (studied) and `target_language` (native).
    - Create-language form (name, code, metadata).
    - Estimate: 2.0h
19. Ensure only `admin` users see the admin pages; block others at the backend and UI routing layer.
    - Estimate: 1.0h

Section subtotal: 5.0h

## Admin UI — Agents & Content Creation

20. Implement `Rule Creation` admin page:
    - Button: "Propose missing rules" — calls backend agent endpoint that runs the grammar-rule agent.
    - Editable list of proposed rules (admin can add/remove/rename entries before approval).
    - Approve button triggers rule generation and preview.
    - Estimate: 4.0h
21. Implement `Word / Expression Creation` admin page:
    - Form to add content + `source_language` + `target_language`.
    - Supports both base words and expressions (agent will detect and route accordingly).
    - Displays agent decisions and interrupts (rule matches, topic candidates, translations) and allows admin approval.
    - Estimate: 4.0h
22. Implement preview/approval UIs for generated forms, translations, sentences, and topic assignments.
    - Estimate: 3.0h
